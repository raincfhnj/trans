| 字段 | 内容 |

| 影响范围 | `trans-windowd` 托盘菜单"Close panel"，以及任何调用 `win32.ClosePanels()` 的路径 |
| 关联 Issue/PR | 无 |

## 1. 问题描述

### 1.1 问题场景

用户桌面上有一个标题以 `trans-panel` 开头、但不是本程序的窗口——例如编辑器里打开的文件 `trans-panel.md`（窗口标题 `trans-panel.md - Notepad`），或浏览器标签页标题 `trans-panel · GitHub`。此时用户点托盘菜单"Close panel"（或因面板异常想关掉面板）。

### 1.2 具体表现

`ClosePanels()` 给**所有标题以 `trans-panel` 开头的可见窗口**发 `WM_CLOSE`：用户的编辑器、浏览器窗口一并被要求关闭。有未保存内容的程序会弹"是否保存"，也可能直接丢掉未保存的更改。

### 1.3 错误信息

**日志信息**：无（该路径不记录关了哪些窗口），只在 `windowd.log` 有一行汇总：

```
2026-10-05T17:47:29 closing 1 panel window(s)
```

## 2. 临时解决方案（可选）

用户侧：避免打开标题以 `trans-panel` 开头的文档窗口。不可接受，故直接修复。

## 3. 根本原因分析

### 3.1 问题分析过程

1. 观察到的表象：审查 `ClosePanels` 时发现匹配条件是 `strings.HasPrefix(window.Title, PanelTitle)`，而面板窗口的标题是**恰好等于** `trans-panel`（`NameConsole(win32.PanelTitle)` 设置的）。
2. 对比同文件的 `HostWindow(title)`：那里是 `syscall.UTF16ToString(buffer) == title` 的**精确匹配**，并且注释专门解释了"标题在 Windows 上不唯一，小窗口要跳过"。同一份代码里两种匹配口径不一致。
3. 推演危害面：前缀匹配会命中 `trans-panel.md - Notepad`、`trans-panel notes` 这类用户自己的窗口，且这些窗口恰好都通过 `Windows()` 的"可见 + ≥200×120 + 有标题"筛选（编辑器窗口比 200×120 大），会真的收到 `WM_CLOSE`。
4. 最终定位：匹配口径错误——"关闭面板"应该只关本程序命名的窗口。

### 3.2 直接原因

`internal/win32/console_windows.go` `ClosePanels()` 用 `strings.HasPrefix(window.Title, PanelTitle)` 选窗口。

**相关代码位置**：`internal/win32/console_windows.go`（修复前约 408 行）

**关键代码片段**：

```go
// 修改前
for _, window := range Windows() {
    if !strings.HasPrefix(window.Title, PanelTitle) {   // "trans-panel.md - Notepad" 也命中
        continue
    }
    call(procPostMessageW, window.Handle, wmClose, 0, 0)
}
```

### 3.3 根本原因

- **设计层面**："哪些窗口是本程序的"缺少一个单一、可测试的判据，散落在 `HostWindow`（精确匹配）、`ClosePanels`（前缀匹配）两处且口径不同。
- **开发层面**：写前缀匹配时默认了"标题等于面板名的只有面板"，没有考虑用户文档恰好以该串开头；破坏性操作（发 `WM_CLOSE`）用了比查询操作更宽的匹配。

### 3.4 为什么没有提前发现

- 代码审查阶段：`ClosePanels` 被当作"收尾清理"路径，评审关注点在"会不会漏关面板"，没人问"会不会多关别人的"。
- 测试阶段：无对应测试（需要真实桌面窗口才能演示），纯文本的匹配规则又没有被抽成可测函数。
- 监控告警：该路径不记录逐窗口结果，误关无任何痕迹。

## 4. 解决方案

### 4.1 根本解决方案

把"哪些窗口是本程序的"收敛成 `match.go` 里的纯函数（与 `Find` 同处，任意平台可测），并按精确名匹配：

**修改文件**：`internal/win32/match.go`、`internal/win32/console_windows.go`

**修改前**：

```go
if !strings.HasPrefix(window.Title, PanelTitle) {
```

**修改后**：

```go
// internal/win32/match.go
// IsPanelWindow says whether a window is one this program drew. The name is
// matched as it stands: a window that merely begins with it is a document of
// the author's — `trans-panel.md` open in an editor — and closing one of those
// is not what "close the panel" means.
func IsPanelWindow(title string) bool {
    return title == PanelTitle
}

// internal/win32/console_windows.go
if !IsPanelWindow(window.Title) {
```

**方案说明**：精确匹配与 `HostWindow` 的口径一致（面板窗口的标题由 `NameConsole(PanelTitle)` 设成恰好 `trans-panel`，三种弹窗同名，一次全部关闭）。曾考虑"前缀匹配但排除已知后缀"，不可枚举、仍然不安全，放弃。

### 4.2 影响范围评估

- 只收窄匹配范围，不会漏关本程序的窗口（标题由本程序设置、恰好等于 `trans-panel`）；
- 若未来 conhost/Windows Terminal 在标题上加前缀（如 `Administrator: `），`HostWindow` 早已同样匹配不上，属于既有约束，不是本次引入。

## 5. 预防措施

### 5.1 代码层面

- [x] 破坏性操作（`WM_CLOSE`、删文件、覆盖数据）的选取条件必须比查询操作更严或相等，不得更宽（已补充进评审清单）；
- [ ] 后续如需"关掉所有本程序窗口"的扩展（设置/划词窗口另起标题），继续走 `IsPanelWindow`，不得再写字符串匹配。

### 5.2 测试层面

- [x] `internal/win32/match_test.go` 增加 `TestOnlyThePanelsOwnWindowsAreThePanels`（已补）：`trans-panel` 是、`trans-panel.md - Notepad`/`trans-panel notes`/空前缀不是。

### 5.3 监控层面

- [ ] 建议 `ClosePanels` 在 `winlog` 记录被关闭的窗口标题，误关可回溯。

### 5.4 流程/规范层面

- [ ] 评审清单补充：凡对"别人家的窗口"执行破坏性操作，选取条件必须与"本程序自己的窗口"判据同源（`IsPanelWindow`）。

## 6. 经验总结（一句话）

> 对用户数据有破坏性的匹配（关窗口、删文件）永远只接受"恰好是我自己的"，前缀、模糊、相似一律不算——你永远不知道用户会不会有个文件叫 `trans-panel.md`。
